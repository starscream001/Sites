# Herbarium — история возникновения комнатного цветоводства

Русскоязычный сайт книги и исторической коллекции по ТЗ от 15.10.2026. Кремовая бумага, тёмно-зелёная палитра, кириллические Cormorant Garamond и Golos Text. Адаптивная статическая библиотека и отдельный серверный редактор без npm-зависимостей.

## Запуск

Нужен Node.js 22 или новее. Устанавливать npm-пакеты не требуется.

```sh
npm run dev
```

Открыть `http://127.0.0.1:4173`. Порт настраивается через `PORT`, интерфейс через `HOST`. По умолчанию сервер доступен только локально.

```sh
npm run build
npm test
```

Сборка создаёт `dist/` и копию готовых публичных файлов в корне репозитория для существующего GitHub Pages (main / root). Не редактируйте сгенерированные корневые HTML/CSS/JS: исходники лежат в `public/`, `content/`, `scripts/`. Список файлов экспорта — `.generated-pages.json`. `dist/` — готовый сайт из 22 HTML-страниц, SVG, CSS, JS, поискового индекса, sitemap.xml и robots.txt. Все публичные страницы доступны напрямую, без клиентского роутера. Ссылки относительные, сайт работает в подпапке `/Sites/`.

## Что реализовано

- Главная, о книге, предварительное оглавление, шесть самостоятельных обзоров с постоянными адресами и якорями разделов.
- История, Азия, Европа, каталог групп растений, галерея, источники, новости, контакты, условия использования.
- Полнотекстовый поиск: заголовки, тексты, регионы, растения, источники и даты; фильтры по разделу и эпохе.
- Хронология: регион, тип события, сортировка по году, достоверность и ссылки на первоисточники.
- Читательский режим: оглавление, переходы, копирование ссылки, локальное избранное, печать/PDF средствами браузера.
- Галерея с увеличением, подписями, датой, автором и лицензией.
- Редактор статей, публикация/снятие с публикации, хронология, растения, библиография, новости, изображения, меню, избранные блоки главной, название и email.
- Загрузка PNG/JPEG/WebP до 2 МБ, проверка сигнатуры, генерация безопасного имени файла.
- SEO: отдельные title/description, canonical, Open Graph, XML sitemap. `SITE_URL` задаёт адрес при сборке; по умолчанию `https://starscream001.github.io/Sites` — это целевой адрес, а не подтверждение включённого хостинга.
- Пропуск к основному содержимому, клавиатура, видимый фокус, системные подписи форм, reduced-motion, печатная версия.

## Редактор

Панель `/admin/` работает **только на Node.js-сервере**. GitHub Pages обслуживает статические файлы и не запускает редактор/API.

Перед запуском задайте `ADMIN_PASSWORD` через менеджер секретов хостинга либо окружение терминала. Минимум 14 символов. Пароль не сохраняется в репозитории; в памяти хранится scrypt-хеш. Не используйте опубликованные примеры паролей.

В локальном терминале пароль можно ввести без вывода на экран:

```sh
read -s ADMIN_PASSWORD
export ADMIN_PASSWORD
npm start
```

1. Откройте `/admin/`, войдите с установленным паролем.
2. Выберите раздел, разверните запись и измените поля. Новая статья по умолчанию является черновиком.
3. ID статьи — уникальное имя латиницей с дефисами. Менять опубликованный ID нежелательно: изменится адрес.
4. Для разделов статьи укажите одинаковое число заголовков и абзацев, каждый с новой строки. ID источников задаются по одному на строку.
5. Для нового источника сначала создайте запись в библиографии, затем свяжите её со статьёй/событием.
6. Нажмите «Сохранить и опубликовать». Сервер проверит структуру и ссылки, создаст резервную копию, пересоберёт сайт. При ошибке данных публикация не выполняется.
7. Снятие статьи с публикации удаляет её HTML из новой сборки и исключает связанные события/растения из публичной выдачи. Данные связей сохраняются в редакторе.
8. Изображение сначала загрузите, затем заполните альтернативное описание, авторство, дату, тип и лицензию в созданной карточке галереи. Нельзя выдавать стилизации за архивные изображения.

Это однопользовательская CMS. Разграничение ролей редакторов не реализовано: при появлении команды потребуется отдельная модель пользователей.

## Хостинг

### Статический сайт

Workflow `.github/workflows/site.yml` проверяет сайт и сохраняет готовую сборку как GitHub Actions artifact. Для размещения загрузите содержимое `dist/` на статический хостинг с HTTPS. Текущая конфигурация GitHub Pages может публиковать прямо из main / root благодаря экспорту сборки. Для альтернативной публикации через Actions включите Pages → GitHub Actions в настройках репозитория и переменную репозитория `ENABLE_PAGES=true`, затем повторно запустите workflow. Deployment job включается только этой переменной.

В статическом режиме редактировать можно через локальную CMS: скачать JSON-копию, заменить `content/site.json`, добавить новые файлы `public/assets/` запустить `npm run build` и закоммитить изменения в `main`. Либо запускайте серверный режим ниже для постоянной панели.

### Сервер с постоянным редактором

Запустите `npm start` на сервере с постоянным диском. Для Docker предусмотрен `Dockerfile`. Передайте `ADMIN_PASSWORD` как секрет, `SITE_URL=https://ваш-домен` и `SITE_ORIGIN=https://ваш-домен`. `SITE_ORIGIN` используется для проверки Origin и защищённой cookie. Завершайте HTTPS на reverse proxy. Пример Caddyfile:

```caddyfile
example.org {
  reverse_proxy 127.0.0.1:4173
}
```

Укажите собственный домен и настройте DNS. При работе через reverse proxy оставьте `HOST=127.0.0.1`; в контейнере применяется `HOST=0.0.0.0`.

Постоянными должны быть `content/`, `public/assets/`, `backups/`. После запуска сервер пересобирает публичные страницы из контента. Перезапуск обнуляет сессии. Сессии действуют 8 часов, cookie HttpOnly/SameSite=Strict; при HTTPS SITE_ORIGIN добавляется Secure. Изменяющие запросы проверяют Origin, вход ограничен 8 попытками на IP за 15 минут. Сервер предназначен для работы за доверенным reverse proxy; ограничитель видит IP прямого соединения, без доверия произвольному X-Forwarded-For.

## Резервные копии и восстановление

Перед каждой публикацией сервер сохраняет предыдущий JSON в закрытой папке `backups/`, удерживает 30 последних копий. Текущий JSON скачивается из панели. Записи, загруженные картинки и версии исходников сохраняйте также вне сервера: Git-история не содержит последующих изменений работающей CMS, пока они не закоммичены.

Полная копия:

```sh
tar -czf herbarium-backup.tar.gz content public/assets backups
```

Восстановление контента: загрузите JSON через «Восстановить JSON», проверьте и опубликуйте. Восстановление изображений: верните `public/assets/` из полной копии. Восстановление исходников — checkout нужного коммита и запуск `npm start`. Проверяйте восстановление на отдельной локальной копии.

## Материалы и ограничения запуска

Предоставленное ТЗ не включает рукопись, подтверждённое авторское оглавление, автора, ISBN, издательство, контакты, домен и архивные изображения. Эти сведения не выдуманы. Шесть небольших текстов — редакционные обзоры, не главы неизвестного автора. Указанное оглавление предварительное. Страницы для Индии, Кореи, Персии, Юго-Восточной Азии и остальных исторических эпох требуют подготовленных и проверенных материалов; их наличие не имитируется пустыми статьями.

Графика в `public/assets/` — новые SVG-стилизации Herbarium, 2026, CC BY 4.0, не исторические документы и не ботанический определитель. Три ботанических этюда условные; карточки каталога описывают группы растений, не полные видовые монографии. Источники — материалы Kew, The Metropolitan Museum of Art, U.S. National Arboretum, ссылки указаны в каждой статье.

Форма сообщений, подписка, аналитика и трекеры отключены: нет адреса получателя, почтового сервиса и сведений об операторе данных. После их предоставления нужно подключить доставку, согласие и окончательные правовые документы. Социальные ссылки не выдуманы. Домен, TLS, регистрация в инструментах веб-мастеров и серверное размещение CMS зависят от выбранного хостинга. Эта поставка в GitHub не подтверждает настройку этих внешних сервисов.

## Проверки

`npm test` проверяет все внутренние ссылки и якоря сгенерированных страниц, H1/метаописания, опасные значения, вход, CSRF, закрытость контента, публикацию и снятие статьи, HTML-экранирование, загрузку изображений, резервные копии и выход. Серверные тесты работают в отдельном временном каталоге и не изменяют рабочие материалы.

Браузерная проверка: главная на 375px и большом экране, меню, поиск, фильтры хронологии, галерея. PageSpeed и полноценный аудит WCAG не проводились. Внешние шрифты загружаются с Google Fonts с локальным fallback Georgia/Arial; при необходимости автономной работы их следует разместить локально с лицензиями.

Предыдущий сайт удалён из рабочей версии по указанию владельца; доступен в предыдущих коммитах Git.
